# Agent Note：Agent Flow 入口节点默认读取本轮用户输入

Status: implemented

[English](2026-11-08-agent-flow-entry-input-default.md) | 中文

## 问题

此前，一次运行的原始请求只会到达带显式 Start 输入边的节点。若 Start 直接执行第一个 Agent，该 Agent（包括交互会话）就不会收到用户启动这次运行时所输入的消息。用户必须额外画一条入口输入线，既消耗注意力，也让运行看起来像配置错误。

## 决策

`GraphExecutor.readsUserInput` 把 Start 的每个直接执行后继视为入口节点，并默认把本轮原始请求交给它。显式的 Start 输入边仍可把请求加入其他节点。解析结果记录在运行的 `userInput` 字段中。输入边仍是非调度引用；保存校验与调度规则不变。

由于该条件已不存在，编辑器中的缺少输入线警告与 composer 认领警告一并移除。非入口节点仍可使用显式 Start 输入边。该默认适用于每个直接 Start 后继，包括并行入口分支。

## 验证

`packages/experimental/agent-flow-runtime/tests/graph.spec.ts` 断言入口节点收到请求、后续节点不收到，以及交互入口在没有显式输入边时也能带请求开场。`packages/experimental/agent-flow-runtime/tests/full-chain.host.spec.ts` 通过生成的 Remote 组合覆盖同一规则。Web L1 仍覆盖带显式输入线的入口流程。

## 已考虑的替代方案

**继续只依赖显式输入线。** 这保留了旧规则，却让最常见的场景必须编辑图；用户在启动运行时已经提供了输入。

**把请求注入每个节点。** 这会把请求泄漏到下游任务，违背“任务只输出自身结果与显式引用”的规则。

**启动运行时自动补输入边。** 这会修改或分叉已保存的文档，使图与运行快照不一致；运行时可以直接提供请求而不改文档。

## 后果

每个流程的入口任务现在都能看到本轮请求，交互入口也不例外。非入口节点仍需显式 Start 输入边才能读取请求。该规则反转了此前的显式输入默认；编辑器不再提示入口缺少输入线。
