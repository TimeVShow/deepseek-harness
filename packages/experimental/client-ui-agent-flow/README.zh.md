# @deepseek-ai/dsh-experimental-client-ui-agent-flow

[English](README.md) | 中文

## 概述

本包在 Web 侧栏增加 **Agent Flow** 入口，打开一个用于编写多 Agent 工作流并观察其运行的面板，另加一个输入框 workflow 选择器。用户可以在画布上编辑流程图与其引用的 agent，标记出那个与用户澄清需求的节点，并把每次运行作为聊天记录打开：每次节点执行一条消息，带状态、交接产物、文件与对话。在输入框选中流程后，下一条消息即作为该流程的一次运行输入，随后客户端把用户带进该运行的对话。读写通过 `agentFlows` 远程命名空间进行，该命名空间由本包自行挂载。

## 使用本包

通过 [`@deepseek-ai/dsh-experimental-agent-flow-profile`](../agent-flow-profile/README.zh.md) 启用本包，它同时提供流程服务、图运行时与本面板。Web 客户端加载器挂载 `./client` 导出；根 Host 导出为空操作。本面板读取一个可选配置字段：`stallNoticeMs`（默认 600000，范围 5000–86400000）指定运行中的运行多久没有新的业务信号——既没有记录到的转变，也没有本客户端所观察的节点会话事件——之后，流程进度卡片提示这段安静期；卡片自身绝不失败、重试或取消运行。

### 编写流程并观察其运行
1. 从侧栏打开 **Agent Flow** 并选择「新建流程」，它会创建一个起始 agent 模板与一张 `start → step → end` 图。
2. 拖动节点来移动位置，在节点连接点之间拖线来连接。新连线默认为**执行**：实线箭头决定顺序并传递来源结果。普通任务有多个执行前驱时会等待全部分支，无需额外添加汇聚节点。来自 **start** 的执行连线只启动任务，不传入用户请求。
3. 点击连线，在属性面板中选择**执行**或**输入**。虚线**输入**箭头引用已产生的结果，不启动目标，也不新增等待条件。输入可以引用任务、条件或汇聚节点，且只能指向任务。需要原始用户请求时，从 **start** 向同一任务再连一次线：第二次会补上缺少的类型并选中新线供检查。每个开始到任务的节点对可各有一条执行线和输入线，其他节点对只保留一条连线。节点的「输入来源」摘要显示所选来源，未连接祖先节点的全部上下文不会被带入。
4. 在那个交接之前与用户澄清需求的节点上勾选「与用户对话」。它的卡片带一个「对话」标记，勾选另一个节点会移动该标记；若对话节点没有来自 **start** 的直接执行连线，Host 会拒绝该流程。
5. 加一个**条件**节点来分支。它读取唯一上游 agent 的 `Result: <词>` 行，只激活词相匹配的那条执行出边，因此这些出边都要填词。它自身不产出内容，并把该 agent 的交接转发下去，所以回到循环里的那条路径依然带着做出这个选择的结论。
6. 保存。Host 校验整张图，面板列出它发现的全部问题。
7. 切到「运行记录」并打开一次运行。页面先给结果而不是聊天全量记录：运行状态、开始时间与用时、执行中的当前节点，以及产出了多少个文件；原始需求折叠着，需要时再展开。随后是每个工作节点一张结果卡片，显示最新轮次（第 N 轮）、状态、结果标记，以及用 Markdown 渲染的最终说明（过长时默认折叠）。说明中的文件链接经右侧栏打开预览：相对目标按该轮的工作目录解析，`#L24` 片段定位到行；面板在屏时主区域先切回运行的对话，预览开在该对话的侧栏。条件节点不成为结果卡片，也不进入状态行——它是执行控制而非交付物——但失败的条件仍会在概览里点名失败步骤。节点产出的文件是紧凑的行——文件名、相对工作区的路径、经右侧栏**预览**，以及复制绝对路径——文档与项目入口优先，最多先显示 6 个，其余收进**查看全部文件**；依赖、环境与缓存目录（如 `.venv`、`node_modules`）收在自己的开关后，该开关同样识别 Windows 盘符与 UNC 地址，打开与复制始终使用原样的记录地址。返工过的节点更早轮次收在**更早轮次**里；**查看执行过程**打开节点的子会话。已完成的运行绝不宣称审查通过：只显示记录的状态与节点自己给出的结果标记。对话节点等用户回复期间，整次运行显示为「澄清中」而不是运行中，该节点自身显示「对话中」并说明这一点，打开的是对话而不是子会话，并提供「结束澄清并继续」用于始终不收敛的对话——它要求该节点停止提问并给出 Result 词，运行本身继续执行。该节点一结算，它会话的输入框即转为不可用，并以原因作为占位文本。有运行在途时列表会轮询，且父会话存活时可取消运行中的运行。

### 从输入框启动一次运行

会话输入框的工具条带有「工作流」选择器。选中一个流程会以本地化的 `工作流:<名称> ` 标记认领输入框；随后提交的消息不再发给 agent，而是作为运行输入启动该流程的一次运行，并绑定当前会话。该运行的对话节点一开启它的会话，客户端就把用户带进去，于是澄清在流程安放它的地方继续；不是本客户端启动的运行绝不会移动用户。空输入会拒绝启动。从草稿中删除该标记即退出选择，与在菜单中选择「不选工作流」等价。当前会话有运行在途时，选择器会显示进行中指示，其菜单项打开面板的「运行记录」标签页。每次打开菜单都会刷新流程列表；没有流程时菜单会指向在面板中创建。

### 在输入框上方跟踪一次运行

一次运行涉及的每个会话——启动它的会话，以及它的每次节点执行开启的会话——在运行结算前都会在输入框上方保留一张**流程进度**卡片，因此被带进节点会话的用户仍然看得到该运行，重载后也能回到它。卡片把持久运行记录与本客户端所观察的节点会话实时活动合在一起：显示阶段（运行中、等待你回复、已完成、失败、已取消）、已进行时长，每个正在执行或即将开始执行的节点一行，带轮次和状态词——活跃节点显示真实阶段（准备执行、等待响应、推理中、生成中、执行工具）及最新信号距今多久，阻塞节点说明它在等待谁，本客户端观察不到的节点则显示记录状态。当多个运行涉及该会话时，卡片内的选择器决定显示哪一个，而不是随机取一项。**查看当前节点**打开对话中节点的会话，没有对话节点时打开正在执行的节点的会话；该节点正在推理时，按钮读作**查看推理过程**，打开的就是普通会话，其中聊天既有的推理折叠区默认收起，由读者自行展开。每个有自己会话的节点行都带一个**详情**入口，因此并行节点与更早的轮次都能到达，又不会把选择器从该运行上移开。**查看完整流程**在面板中打开运行记录。只有运行在运行中且其父会话仍有存活的 agent 时才出现**取消**；它的结果以运行自身记录的状态为准，绝不断言一次取消。卡片只在运行的对话节点确实空闲时才显示等待用户：该会话正在处理回复、或已提交的消息尚未落地时，卡片读作运行中，节点行显示流报告的阶段。只有仍在执行的节点会被判静默：某节点超过 `stallNoticeMs` 没有任何业务信号——本客户端观察它时没有会话事件，观察不到时没有记录到的转变——时，卡片会在无活动提示中逐个点名该节点，因此忙碌分支无法掩盖安静分支。已结算的执行保留最后观察供阅读，但绝不会触发提示；持续到达的推理或工具流绝不会触发它；运行正在等待的节点属于设计上的空闲；节点自身的跟随流失败时读作「连接中断」而不是安静；提示只在运行本身仍在执行时出现。名册读取失败期间，卡片标记为最后已知状态并保留上一次的列表；下一次读取成功即清除该标记。

### 管理 Agent

**Agent** 标签页列出每个 Agent 及其被多少个流程引用；一个都没有时会提示创建第一个。一个 Agent 保存人设与模型路由。模型从系统已配置模型的下拉中选择——没有手动输入——且必须选择后才能保存；已保存但目录不再提供的路由保持可选，编辑不会改写它。一个节点 agent 完全由其模板加节点指令决定，Host 在节点启动时读取模板。

## 理解实现

<details>
<summary>实现内部 —— 点击展开</summary>

`mount.ts` 挂载本包生成的远程贡献，然后通过 `ctx.slots.inject` 注册四个界面：一个带 key 的 `main` 面板条目、其 `sidebar.panellist` 条目、输入框的 `conversation.input.left` workflow 选择器，以及输入框的 `conversation.input.dock` 流程进度卡片。卡片与选择器的在途指示寻址哪些会话，由 `run-view.ts` 中的一条规则决定：一次运行涉及它的父会话与每个被节点执行记录为 agent 会话的会话；卡片显示的每个记录事实——阶段、节点行、最近转变、已结算对话的阻塞原因——都通过该模块从运行记录派生。卡片的实时一半由另一条独立来源供给：`activity-tracker.ts` 只保留名册报告为执行中或对话中的节点执行所属的会话，通过 `activity.ts` 折叠它们有序的事件流，得到阶段、业务时间戳、未结束的工具调用与面向用户的实时状态，并把该观察发布到控制器的 `nodeActivity`——绝不包含推理文本本身。折叠读取 assistant 流片段（推理、正文、工具调用）与持久的 turn、step、message、工具事件，因此阶段跟随模型而无需第二套协议，也不复制内容；节点执行结算或运行结算时跟踪器释放该会话，面板卸载时一并释放。观察在阶段、未结束工具或实时状态变化时发布，否则每 1 秒新信号最多发布一次，因此 token 流每秒只渲染一次，而不是每个片段一次。卡片的阶段由记录加该实时状态决定：`conversing` 节点对应的会话确实在工作、或用户的回复尚未落地时，不再读作等待用户；无活动提示衡量两个来源中最新的业务时间戳，因此持续推理不会被误报为静默。运行页通过 `results-view.ts` 投影同一批记录：工作节点按最新轮次归组，结构性 start 与 end 节点压缩成一行状态，条件绝不成为结果——既不上卡片也不进状态行，其失败仍经概览浮出；节点的文件清单只为展示而拆分——文档与项目入口优先，最多先给六个，依赖、环境与缓存目录收在开关后——绝不改写运行时交给后续节点的记录。交接说明经共享 Markdown 组件并带上文件打开委托渲染，目标按其轮次的工作目录解析，并带着定位行打开面板的资源地址；所有文件操作复用同一地址，由侧栏负责加载与失败状态，且面板在屏时先切回运行的对话——侧栏只在对话处绑定会话面；等待中的这次打开归属插件生命周期——卸载即丢弃、切换被拒即取消——重复的同一请求并入已在等待的那一次。控制器拥有一个通过 inject `hooks` 舱发布的快照 store，因此组件用标准 `useAgentFlow` 选择器读取而从不接触 `ctx`；它还在有运行在途时轮询运行列表，没有时停止。它在挂载时就读取一次名册——早于任何面板打开——因为正是这次读取通过 `ctx.conversation.blocks` 升起已结算对话的输入框阻塞；该阻塞从持久运行记录派生，因此重载后依然成立。选择器的选中状态派生自输入机发布的认领——选中流程会通过作用域 begin-command 事件下发一个认领，其 submit 经远程命名空间启动运行并立即并入 store，因此在途指示从不等待轮询。这次并入还会把该运行记为本客户端启动的运行；随后每次轮询都会在其对话节点的会话首次出现时把用户带进去，并在该运行结算、或发现它没有对话节点时丢弃这个意图。图几何位于 `graph.ts`：节点坐标持久化在文档上，没有坐标的节点按距 start 的最短执行距离布局。每个可达 id 只访问一次，所以有环和未完成的草稿也有界；输入边始终可见，但不影响布局。每条连线都有类型标签、箭头和宽命中区。开始节点对的输入曲线与执行曲线分开，使两条线都可选中。画布编辑通过单一回调修改草稿，因此保存总是发送 Host 校验的完整文档。新建流程必须显式选择入口 Agent；若所选模板已被删除则清除该选择，模板全部删除时创建改用中性 Starter。对话入口没有 start 输入线时，检查器会就地警告，composer 的认领也会在输入卡片上方持续显示同一警告。刷新只由最新的响应提交；它会合并在响应在途期间本客户端确认的启动，且不会把已终结的运行退回 running。慢刷新期间到达的轮询 tick 会合并为一次后续刷新，因此比轮询间隔更慢的响应仍能提交，而不会被永久作废。保存 Agent 表单会采纳分配的 id，流程名直接编辑草稿，因此保存响应不会回滚之后的编辑。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

这些限制描述本面板目前做不到或需要特殊运维注意的地方。它们是当前包约束，不是任务 backlog。

- **运行记录靠轮询，实时阶段走事件流**——有运行在途时，运行名册与节点执行按间隔刷新，因此两次轮询之间结算的运行会显示得晚一些，进入对话的那次跳转也落在轮询节拍上而非立即发生；本客户端所观察的节点会话，其阶段在两次轮询之间直接来自该会话自己的事件流，客户端无法解析的会话则在下一次轮询前显示记录状态。读取失败时保留上一次的列表并标记为最后已知状态，而不是清空卡片。
- **没有新请求头的步骤读作准备执行**——会话日志只在请求头首次出现或发生变化时记录一条，而不是每次调用都记，因此一个回合的后续步骤在首个流式输出到达前可能一直显示**准备执行**。日志中没有可按请求读取的派发事件。
- **文件在运行的对话旁打开，而不是在面板旁**——面板占据主区域时右侧栏没有会话面，因此**预览**与说明中的文件链接会把主区域切到运行的父对话，并在那里打开预览；面板保留同一运行供返回。要做面板内预览，需要侧栏提供主面板可打开的会话面，目前没有。
- **推理详情打开节点的会话**——卡片上的入口把节点会话切换到主对话，由既有推理折叠区展示流式内容；当前对话旁没有常驻的推理面板。要做原地查看，需要在右侧栏新增一个会话预览页类型，本包尚未注册。
- **无节点级重试或续跑**——失败的运行即终止；必须从头重新启动该图。
- **单一会话父级**——一次运行的节点 agent 共享父会话的谱系与工作区。
- **无稳定性承诺的实验原型**——本包公开发布，但契约在孵化期内可自由变更。
